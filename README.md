# 规则树（RuleTree）

一个独立的小应用，专门试一件事：把「如果……则……否则……」做成可以复用的结构，而不是一条条写死的任务。

第一个用例就是最典型的那句：连上家里 Wi-Fi 就静音，断开就恢复正常。

和 RoutineX 是两个独立的应用，共用「定时执行」这个想法，但代码、包名、存储都不相干。RoutineX 那边的定位是「到点做一件事」，不打算把分支塞进去，那样会越滚越大。

## 核心是树，不是列表

一条规则 = 一个触发器 + 一棵动作树。树只有三种节点：

```
action   叶子，真正干活：改铃声、调音量、开应用、发通知
if       条件 + then 一组 + else 一组，两边都可以再放任意节点
seq      按顺序执行一组子节点
```

因为 then / else 里放的是节点数组，节点又能是 if，所以嵌套是天然的。第一版的界面只暴露「一个条件 + 两组动作」，但存下去的结构已经是任意深度。

完整的字段定义、各类型的参数、兼容性策略，都写在 [DATA-MODEL.md](DATA-MODEL.md)。那是这个项目最重要的文件，改格式前先看它。

存储位置：应用私有目录下的 `rules.json`，格式是 `{"version":1,"rules":[...]}`，写入走「临时文件 + 改名」，断电不会写坏。

## 已经能用的

**触发器**：Wi-Fi 连上 / 断开 / 任意变化，插上电源 / 拔掉 / 任意变化，收到通知（可按应用和关键词筛），
蓝牙设备连上 / 断开（可指定设备），每天固定时间（可指定星期），手动。

**条件**：连着 Wi-Fi（任意或指定 SSID）、正在充电、电量高于 / 低于某百分比、时间在某个区间（支持跨零点）、
星期几、屏幕亮着、处于锁屏、免打扰、三种铃声模式、深色模式、连着蓝牙、插着耳机、当前应用是、总是成立。
所有条件都能取反，也能用「并且 / 或者」把多条串成一组。

**动作**：铃声三态、媒体 / 铃声 / 闹钟 / 通知四路音量、免打扰开关、振动、媒体键（播放暂停 / 上一首 / 下一首）、
手电筒、打开网址、写剪贴板、TTS 朗读、HTTP 请求、打开应用、发通知、等待、执行前确认、等到解锁、主动停止，
无障碍那一组（返回、主屏、最近任务、通知栏、快捷设置、锁屏、点击坐标、滑动、截屏、手势序列录制回放），
以及一组走 root 的系统开关（飞行模式、移动数据、Wi-Fi、蓝牙、NFC、定位、热点、亮度、屏幕超时、
自动旋转、深色模式、字体大小、屏幕密度与分辨率、充电不息屏、立刻熄屏、强行停止应用、任意 shell 命令）。

**界面**：主界面是规则卡片；权限单独一页，五项各写清用途和状态，点一下跳到对应设置；
选 Wi-Fi 时给一个列表（当前连接 + 附近扫到的 + 手动输入），不用逐字敲名字。

编辑页是递归的：任何一组动作里都能再嵌一层「条件分支」，缩进显示，点「改条件」单独设置判断。
条件也能组合：选「组合条件」后逐条加，顶部一行切换「并且 / 或者」，组里还能再套组，点进去编辑。
组里的条目长按行首的 `≡` 可以直接拖动调顺序，短路求值时顺序是有意义的。

定时规则不靠轮询，走 `AlarmManager`：每条规则一个精确闹钟，跑完立刻排下一次，
开机和改规则时整体重排一遍。没拿到精确闹钟权限就退化成 10 分钟窗口，到点可能晚几分钟。

**测试模式**：卡片上的「运行」和编辑页的「测试运行」都能选「立刻 / 5 / 10 / 30 / 60 秒后」，
也可以自己填秒数。延迟跑走的是另一个闹钟（`TEST_FIRE`），跟日常定时互不干扰，
到点就算应用在后台、屏幕锁着也照跑。延迟跑之前会先把当前编辑内容落盘——闹钟到点得能从存储里找回规则。

## 实测记录

在小米 17 Pro（Android 17）上跑通了完整链路：

```
21:31:19  Wi-Fi 变为 已断开（来源 网络回调）
21:31:19  条件[连着 Wi-Fi] = false
21:31:19  走 else（1 步）
21:31:19  铃声模式已设为 normal（当前=2）

21:31:29  Wi-Fi 变为 已连接（来源 网络回调）
21:31:31  条件[连着 Wi-Fi] = true
21:31:31  走 then（1 步）
21:31:31  铃声模式已设为 silent（当前=0）
```

关 Wi-Fi 铃声回到正常，开 Wi-Fi 铃声变静音，两边都对。

## 小米上踩的两个坑

**一、隐式广播递不过来。** manifest 里注册 `android.net.wifi.STATE_CHANGE` 的接收器，实测一条都收不到，系统日志里能看到广播发出去了，但没我们的份。改成前台服务里 `registerNetworkCallback`，才拿得到事件。那条 manifest 接收器现在留着当别的 ROM 的兜底。

**二、`onAvailable` 不等于「已连接」。** 回调触发时立刻查 `getActiveNetwork()`，往往还是旧的或者空的，条件判成 false，走错分支。现在连上事件会先等 1.2 秒，再确认一次状态才执行。断开事件不需要等，立即执行。

这两条都不是理论推演，是踩出来的，日志在 `files/rt.log`。

## 权限

| 权限 | 用途 | 不给会怎样 |
| :--- | :--- | :--- |
| 定位 | 读 Wi-Fi 名字（SSID） | 只能判断「连没连 Wi-Fi」，判不了具体哪个 |
| 勿扰访问 | 改铃声和音量 | 动作被忽略，日志里记一句 |
| 通知 | 发通知动作、前台服务 | 发通知无效，服务照跑 |
| 通知使用权 | 用「收到通知」触发规则 | 这类触发器永远不响，其它功能正常 |
| 蓝牙连接 | 读蓝牙设备名和 MAC | 只知道有设备连上断开，限定设备的规则不触发 |
| 精确闹钟 | 定时规则到点就跑 | 退化成 10 分钟窗口，可能晚几分钟 |
| 无障碍 | 返回 / 主屏 / 锁屏 / 点击 / 滑动 / 截屏 / 录手势 | 这些动作直接跳过，其它功能正常。只申请手势和截图能力，加一个「当前是哪个应用」的包名 |
| Root | 系统开关那一组动作 | 动作失败并记日志，其它功能不受影响 |
| WRITE_SECURE_SETTINGS | 亮度、超时、旋转、深色模式可以直接写 | 自动退回 root 跑 `settings put` |

主界面顶部会把缺的项列出来，点按钮直接跳对应设置页。

小米还要额外给「自启动」和「电池无限制」，否则前台服务会被清掉。这个应用没有做引导，用户自己开。

## 条件组合的一个例子

「连上家里 Wi-Fi、电量还够、而且不是在充电」三个条件同时成立才静音：

```json
{
  "type": "group", "op": "all",
  "children": [
    { "type": "wifi_connected", "params": { "ssid": "Home-5G" } },
    { "type": "battery_below", "params": { "pct": 20 }, "negate": true },
    { "type": "charging", "params": {}, "negate": true }
  ]
}
```

`op` 换成 `any` 就是「任一条成立即可」。`children` 里也可以再放一个 `group`。

## 还没做

- 蓝牙触发只在有已配对设备的机器上跑过一次，缺更多真机样本
- TTS 朗读依赖系统里的语音引擎，测试机上没装，代码走通了但没听到声音
- 热点、NFC、飞行模式的具体命令跟 ROM 有关，只验证了 Wi-Fi / 蓝牙 / 亮度 / 超时 / 深色模式
- 手势序列只能录点按和滑动，没有按键和等待
- 没有导入导出界面，`rules.json` 可以直接拷
